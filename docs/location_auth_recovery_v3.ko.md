# 위치 수신 로그인 만료 복구

## 목적

데스크톱에서 위치 전송이 성공하더라도 웹의 Google 인증이 만료되면 위치를 받지 못할 수 있다. 웹에 로그인 정보가 남아 있는 것과 위치 WebSocket 인증 성공 여부를 구분한다. 과거 문의의 정확한 원인이 확인된 것은 아니며, 이 문서는 동일한 증상을 예방하는 변경이다.

## 백엔드

기존 `/ws?token=...` 계약과 정상 위치 전달 형식은 유지한다. Google 토큰 확인은 스레드 풀에서 실행하고 요청 제한 시간은 5초다.

| 결과 | 상태 이벤트 | WebSocket 종료 코드 | 프론트 동작 |
| --- | --- | --- | --- |
| Google 400/401 | `auth-required` | `4401` | 토큰 갱신 후 한 번 재연결, 실패하면 재로그인 안내 |
| 시간 초과·통신 오류·429·5xx·비정상 응답 | `reconnecting` | `1013` | 재로그인 요구 없이 재시도 |

오류 상태를 브라우저에 전달하기 위해 WebSocket을 수락한 뒤 상태 이벤트와 종료 코드를 보낸다. 인증 실패 연결은 위치 구독에 진입하지 않는다. 이벤트 형식은 `{"type":"location_connection_status","status":"auth-required"}` 또는 `reconnecting`이다. 로그에 토큰이나 Google 응답 본문을 추가하지 않는다.

## 프론트 반영 내용

- 페이지 진입·이동, 탭 복귀, 온라인 복귀 및 토큰 만료 전에 세션을 확인한다. 자동 확인은 중복 실행을 방지한다.
- 갱신 불가(`invalid_grant` 또는 refresh token 없음)는 `ReauthenticationRequired`로 전달하고 재로그인 버튼을 표시한다.
- 일시 갱신 실패는 `AccessTokenRefreshUnavailable`, 사용자 정보 조회 실패는 `UserInfoUnavailable`로 구분한다. 자동 로그아웃하지 않으며 재확인 버튼과 일시 오류 안내를 표시한다.
- 갱신 재요청은 30초 간격으로 제한한다. 동일 서버 프로세스의 동시 갱신 요청은 하나로 합친다.
- 위치 연결이 인증 실패로 종료되면 갱신을 한 번 요청한다. 인증 실패가 반복되면 자동 재연결을 멈추고 재로그인을 안내한다.
- 온라인 복귀 시 위치 연결을 다시 생성한다.

## 배포 및 확인

DB 변경과 데스크톱 재배포는 필요 없다. 백엔드를 먼저 배포해도 기존 프론트는 `4401`을 인증 실패로 처리한다. 안내와 갱신 복구 기능은 프론트 배포까지 완료해야 적용된다.

1. 정상 로그인 상태에서 위치·레이드 상태 수신을 확인한다.
2. 탭을 오래 비활성화했다가 돌아와 위치 수신이 복구되는지 확인한다.
3. 인증 갱신이 취소된 계정에서 재로그인 안내가 나오고 로그인 후 위치 수신이 복구되는지 확인한다.
4. 인증 서버 일시 장애 시 로그아웃 안내 대신 재시도 상태가 유지되는지 확인한다.

자동 검증은 Google 응답을 모의한 인증 테스트, 격리된 Redis 위치 수신 테스트, 프론트 갱신·재연결 테스트 및 TypeScript/ESLint 검사로 수행한다. 실제 운영 Google 로그인·브라우저 복귀 시나리오는 배포 후 별도 확인한다.

# 데스크톱 사용자 지정 감시 경로 수집 V3

## 목적과 전송 시점

사용자가 지정한 감시 폴더의 경로 패턴을 분석하고 자동 탐색을 개선하기 위한 수집이다. 설정 동기화·복원 기능이 아니며 경로 조회 API는 제공하지 않는다. 이메일·사용자 ID는 받거나 저장하지 않는다.

클라이언트는 **사용자가 폴더를 선택하고 로컬 설정 저장에 성공한 직후** 해당 종류의 경로 한 건을 전송한다. 스크린샷과 로그 경로는 각각 독립적으로 전송한다. 앱 시작 시 기존 경로를 재전송하지 않는다.

API 호출은 로컬 저장·감시 시작과 분리한다. API 타임아웃·검증 오류·서버 오류가 로컬 저장 성공을 취소하거나 감시 동작을 중단하면 안 된다. HTTP 실패 때문에 폴더 선택을 다시 요구하지 않는다. 초기 정책은 자동 재시도나 시작 시 재전송 없이 다음 사용자 선택을 수집하는 방식이다.

## 요청과 성공 응답

`POST /api/where-am-i/v3/path-reports`

```json
{
  "path_type": "screenshot",
  "path": "D:\\Games\\Escape from Tarkov\\Screenshots",
  "app_version": "3.0.0"
}
```

세 필드는 모두 필수다. JSON serializer를 사용해 역슬래시를 인코딩한다.

| 필드 | 규칙 |
|---|---|
| path_type | 정확히 `screenshot` 또는 `log` |
| path | 문자열 1~4096자. 공백만 있는 값, 제어 문자(NUL·개행·탭 등)는 거부 |
| app_version | 문자열 1~64자. 공백만 있는 값·제어 문자는 거부. 특정 버전 표기 형식은 강제하지 않음 |

추가 필드는 허용하지 않는다. 이메일이나 created_at을 보내지 않는다. 드라이브 경로, UNC 경로, 한국어 경로를 서버 OS 기준으로 변환하거나 대소문자·역슬래시를 변경하지 않는다. 서버에서는 경로의 존재 여부를 검사하거나 파일·디렉터리에 접근하지 않는다. 클라이언트의 폴더 선택기가 선택한 경로를 보내되, 서버는 Windows 절대경로 문법을 강제하지 않는다.

성공은 트랜잭션 커밋 후 HTTP 200으로 응답한다.

```json
{"status":200,"msg":"OK","data":true}
```

## 실패와 기존 정책

- 입력 검증 실패: HTTP 422, FastAPI 기본 `detail` 배열.
- DB 저장 실패: HTTP 503, `{ "detail": "PATH_REPORT_STORAGE_UNAVAILABLE" }`. 저장 성공으로 처리하지 않는다.
- 기존 공통 HTTP 미들웨어의 차단·호출 제한에 따라 410 또는 429 등이 올 수 있다. 제한 응답은 JSON 본문이 없을 수도 있다.
- 기존 데스크톱 API와 동일하게 별도 Bearer 인증·이메일 검증은 추가하지 않는다. 공통 `API_RATE_LIMIT_PER_MINUTE`(기본 IP별 워커별 분당 1000회)에 포함된다. 엔드포인트 전용 제한이나 분산 제한은 이번에 추가하지 않는다.
- 클라이언트는 제한 시간을 둔 요청을 사용하고 응답 실패를 로컬 폴더 저장 실패로 표시하지 않는다.

## 개인정보 마스킹

`C:\Users\실제이름\...` 같은 개인 폴더명은 **클라이언트에서** `C:\Users\<user>\...`로 마스킹한 뒤 전송하는 것을 권장한다. 서버는 전달받은 문자열을 그대로 저장하므로 미마스킹 값이 오면 실제 사용자 폴더명도 저장된다. 이메일은 별도 수집하지 않는다.

새 저장 코드에서는 경로나 전체 DB 예외 문자열을 로그에 남기지 않는다. DB 예외에는 바인딩된 경로가 포함될 수 있어 예외 종류만 기록한다.

## 저장·중복·보관 정책

테이블: `where_am_i_path_reports`

| 컬럼 | PostgreSQL 타입 | 의미 |
|---|---|---|
| id | bigint identity PK | 서버 발급 기록 ID |
| path_type | varchar(16) NOT NULL | screenshot / log |
| path | text NOT NULL | 전달된 경로 문자열 |
| app_version | varchar(64) NOT NULL | 실행 파일 버전 |
| created_at | timestamptz NOT NULL DEFAULT now() | 서버 수집 시각 |

동일 경로·버전·종류라도 정상 요청마다 새 행을 추가한다. 중복 제거와 idempotency key는 없으므로 통신 실패 후 재전송하면 중복 저장될 수 있다.

보관 기간은 미확정이다. 이번 구현은 자동 삭제·정리 작업을 추가하지 않는다. 추후 보관 기간을 확정해 별도 적용한다. 수집된 경로를 실행 설정으로 읽거나 복원하지 않는다.

## 배포

1. V3 PostgreSQL DB에 `sql/migrations/20261017_where_am_i_path_reports.sql`을 적용한다. 기존 테이블·데이터를 변경하지 않는 추가용 SQL이며 재실행 가능하다.
2. 백엔드를 배포하고 실제 API의 성공 응답·DB 행을 확인한다. 신규 환경 변수는 없다.
3. 데스크톱 앱에 전송·마스킹 처리를 배포한다. 앱이 API보다 먼저 배포돼도 실패가 로컬 기능에 영향을 주지 않아야 한다.

`platform_db.sql`에도 동일한 테이블 정의를 반영했다. 서버 시작 시 자동 마이그레이션은 수행하지 않는다.
